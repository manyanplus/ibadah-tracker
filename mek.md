badah Tracker — Spesifikasi & Panduan Vibe Coding (Versi Browser Preview)Dokumen ini adalah instruksi utama untuk AI coding assistant.Pengembangan dilakukan menggunakan VS Code, dan aplikasi dijalankan serta diuji langsung melalui Browser Preview (seperti Live Server atau Vite dev server) di laptop, sehingga tidak memerlukan setup Android SDK, JDK, maupun kabel USB.1. Ringkasan ProyekIbadah Tracker adalah aplikasi web (mobile-first) untuk mencatat checklist sholat lima waktu setiap hari dan melihat riwayatnya.Versi pertama dibuat offline-first:Tidak membutuhkan akun atau login.Tidak membutuhkan server atau database online.Data disimpan langsung di browser menggunakan LocalStorage.Aplikasi dapat digunakan secara offline setelah halaman dimuat.Catatan Etika: Checklist merupakan catatan pribadi pengguna, bukan penilaian atau penghakiman. Jangan menampilkan pesan yang menghakimi atau mengasumsikan alasan ketika suatu checklist belum dicentang.2. Teknologi & Arsitektur SederhanaUntuk memudahkan pengujian cepat di browser tanpa setup yang berat:Struktur: HTML5, CSS3 (Tailwind CSS via CDN atau CSS standar), dan Vanilla JavaScript (disarankan tanpa build step untuk MVP agar langsung jalan).Penyimpanan Lokal: localStorage browser (menggantikan Room Database).Editor: Visual Studio Code.Preview: Ekstensi Live Server di VS Code atau langsung membuka file index.html di browser (Chrome/Edge/Firefox) dengan mode tampilan HP (Responsive Design Mode / DevTools).3. Workflow yang Harus DigunakanAlur utama sangat cepat dan ringan:Pengguna meminta AI membuat atau mengubah kode di VS Code.AI menjelaskan file yang dibuat atau diubah.Pengguna membuka atau me-refresh Browser Preview (misal: http://localhost:5500).Pengguna menguji fitur langsung di browser (disarankan mengaktifkan mode tampilan mobile F12 -> ikon HP/Tablet).Jika ada perubahan kode, simpan file (Ctrl+S / Cmd+S) dan lihat perubahan secara instan.4. Persiapan Lingkungan KerjaCukup siapkan:VS CodeEkstensi Live Server di VS Code (opsional, agar auto-reload saat file disimpan).Browser Modern (Google Chrome, Microsoft Edge, Brave, atau Firefox).5. Fitur MVP (Minimum Viable Product)5.1 Dashboard UtamaTampilkan:Header: Nama aplikasi (Ibadah Tracker) dan tanggal yang sedang dipilih (default: hari ini).Ringkasan Progress:Teks jumlah selesai, misalnya: "3 dari 5".Persentase selesai, misalnya: "60%".Progress bar visual sederhana.Daftar Checklist: Subuh, Dzuhur, Ashar, Maghrib, dan Isya.Navigasi Tanggal: Tombol cepat untuk pindah ke hari sebelumnya (<), hari ini, atau pemilih tanggal (<input type="date">).Interaksi: Setiap item memiliki nama sholat dan checkbox. Ketika dicentang/dihapus centangnya, angka progress langsung berubah dan data otomatis tersimpan ke localStorage.5.2 Riwayat Harian (Terintegrasi via Pemilih Tanggal)Pengguna dapat memilih tanggal mana saja melalui pemilih tanggal di bagian atas.Saat tanggal diganti, daftar checklist otomatis memuat data untuk tanggal tersebut.Jika tanggal yang dipilih belum pernah diisi, tampilkan kelima sholat dalam keadaan belum dicentang.Mengubah checklist pada tanggal tertentu tidak boleh mengubah data tanggal lain.5.3 Rumus Ringkasan$$\text{Persentase} = \text{Math.round}\left(\frac{\text{jumlah selesai}}{5} \times 100\right)$$6. Struktur Data (JSON di LocalStorage)Gunakan satu key utama di localStorage, misalnya ibadah_tracker_data. Struktur datanya menggunakan objek yang dikelompokkan berdasarkan tanggal lokal format ISO (YYYY-MM-DD):{
  "2026-11-17": {
    "Subuh": true,
    "Dzuhur": true,
    "Ashar": false,
    "Maghrib": false,
    "Isya": false
  },
  "2026-11-16": {
    "Subuh": true,
    "Dzuhur": true,
    "Ashar": true,
    "Maghrib": true,
    "Isya": true
  }
}
Aturan Penting DataPastikan format tanggal menggunakan waktu lokal pengguna (bukan UTC toISOString() mentah yang bisa bergeser hari karena zona waktu).Data harus tetap bertahan saat halaman di-refresh atau browser ditutup dan dibuka kembali.7. Desain Antarmuka (Mobile-First)Buat container utama dengan lebar maksimal sekitar 480px di tengah layar agar terlihat seperti aplikasi HP meskipun dibuka di browser laptop.Desain minimalis, bersih, dan mudah dibaca.Jarak antar-elemen dan area sentuh (tap target) cukup besar dan nyaman diklik.Gunakan warna netral (putih/abu-abu lembut) dengan satu warna aksen yang menenangkan (misalnya hijau emerald atau teal).Hindari statistik yang rumit atau penuh sesak.8. Struktur Kode yang DisarankanUntuk menjaga kesederhanaan, cukup gunakan 3 file standar:ibadah-tracker/
├── index.html      # Struktur halaman dan elemen UI
├── style.css       # Styling mobile-first & tampilan bersih
└── app.js          # Logika tanggal, checklist, kalkulasi, & localStorage
(Catatan: Jika ingin lebih praktis lagi untuk preview instan, seluruh kode dapat digabung dalam satu file index.html terlebih dahulu, lalu dipisah jika sudah stabil).9. Cara Kerja AI Coding AssistantIkuti aturan ini sepanjang pengerjaan:Jelaskan file yang akan dibuat atau diubah sebelum menulis kode.Kerjakan secara bertahap dan jaga agar kode tetap sederhana.Berikan kode lengkap (bukan potongan/pseudocode) agar pengguna bisa langsung copy-paste dan menjalankannya.Setelah memberikan kode, beritahu cara membukanya di browser dan apa yang harus diuji.Jangan menambahkan fitur login, backend, iklan, atau library kompleks yang tidak perlu.10. Tahapan PengerjaanTahap 1 — Tampilan Dasar & InteraksiBuat struktur HTML, CSS mobile-first, dan JavaScript dasar sehingga 5 waktu sholat tampil, bisa dicentang, dan progress bar/persentase berubah secara real-time.Tahap 2 — Penyimpanan Lokal (localStorage)Hubungkan status checkbox agar tersimpan otomatis berdasarkan tanggal hari ini, dan tetap ada saat browser di-refresh.Tahap 3 — Pemilih Tanggal & RiwayatTambahkan navigasi/input tanggal agar pengguna bisa melihat dan mengedit catatan ibadah di tanggal-tanggal sebelumnya tanpa saling menimpa.Tahap 4 — Poles UI & Pengujian AkhirRapikan tampilan, pastikan responsif di layar HP, dan uji pergantian tanggal serta kondisi offline.11. Kriteria Selesai MVP[ ] Aplikasi berjalan lancar di browser preview tanpa error di console.[ ] Tampilan rapi menyerupai aplikasi mobile (mobile-first).[ ] Lima waktu sholat tampil dengan jelas.[ ] Checkbox dapat diklik dan langsung memperbarui hitungan (X dari 5) serta persentase.[ ] Data tersimpan di localStorage dan tidak hilang saat halaman di-refresh.[ ] Pengguna dapat berpindah tanggal untuk melihat atau mengisi riwayat hari lain.[ ] Data antar-tanggal terpisah dengan aman (tidak saling menimpa).12. Instruksi untuk MemulaiLangsung mulai dari Tahap 1 & 2 (karena berbasis browser tidak memerlukan instalasi SDK). Buat kerangka aplikasi yang sudah bisa menampilkan UI mobile-first, menghitung progress checklist, dan menyimpannya ke localStorage untuk tanggal hari ini, lalu pandu pengguna cara membukanya di browser preview.
